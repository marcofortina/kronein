# Functional cache blocks

`regtest_chain199.json` contains 199 genuinely mined Kronein regtest blocks.
It is static, checked-in test data, not generated by CI. The original functional
cache mining recipe is preserved: eight batches rotating among four fixed
destinations, seven batches of 25 blocks and one of 24. At height 199 the first
three destinations each have 25 mature and 25 immature rewards; the fourth has
25 mature and 24 immature rewards (for spending in the next block).

When the functional cache is missing, the framework starts a clean node and
submits each serialized block via `submitblock`. Normal consensus validation,
including RandomX proof-of-work and registry commitments, remains enabled.
The framework checks the format, network, genesis, destinations, block count,
tip and registry root. Invalid or incompatible fixtures fail; there is no
automatic fallback to mining. Database files are built locally, not distributed.

The existing stopped-cache copying mechanism is unchanged. Each test gets its
own datadir. Block 200 is still mined with a recent timestamp to exit IBD. Tests
starting from a clean chain and all subsequent mining are unchanged. This file
is separate from the C++ 100-block fixture, which uses a different payout recipe.

## Explicit regeneration

Use a normal, non-fuzz daemon build. From the repository root, with an existing
build in `build`:

```sh
python3 test/functional/create_cache.py --configfile=build/test/config.ini \
    --generate-fixture=build/regtest_chain199.json
```

The generator starts from genesis, uses the original mining RPCs, and never reads
the old fixture. It refuses to overwrite its output file. Generate twice and
compare the outputs before replacing `test/functional/data/regtest_chain199.json`.
Review changes; never alter consensus or test expectations simply to accept a
new fixture. Do not change timestamps in already mined blocks.

After replacement, run `feature_framework_cache.py` with a fresh `--cachedir`,
then run it again with the same cache to cover reuse. Also run representative
wallet and mining functional tests. `create_cache.py` without the regeneration
option only loads the static fixture, as it does in CI.
